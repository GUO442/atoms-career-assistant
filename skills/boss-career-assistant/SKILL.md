# BOSS 求职助手

保留用户原有目标，按当前进度续跑：登录 → 真实经历与偏好 → 搜索岗位 → JD 匹配 → 用户选岗 → 定制简历 → 反馈。

## 执行

- 登录使用已有 `boss-login` Skill 的流程。登录表单/账户状态必须可见核验。当前已发现“登录/注册”和“我要找工作”均短暂到登录地址后跳回首页，未确认原因；不要循环点击或宣称已登录。
- 先读已有简历和偏好，再一次性补齐城市、岗位、薪资等缺失条件。没有简历时可以说明岗位条件，不能判断个人匹配或编造经历。
- 浏览器操作遵循当前工具文档，使用 boss-web-tools 的实抓页面搜索与详情接口读取真实 JD，不导出凭据、不猜测未验证接口。保存来源链接、岗位名称、公司、城市、薪资口径、JD原文和采集日期。
- 匹配报告逐条列出JD要求、简历证据、缺口和建议；区分硬条件不满足与信息未知，不编造精确录用概率。
- 为用户选定的每个岗位分别生成简历正文与修改说明，保持任职单位、日期、学历与成果真实。新数字或经历必须先得到用户事实确认。
- 每份简历关联岗位链接与版本，保留原始简历。用户未要求投递时，交付文件后停止外部写入。

## GUI 与工具边界

本地 GUI 源码位于本次交付目录 `career-assistant`，以 `server.py` 为入口。网页查询使用 `boss-web-tools` Skill 封装的页面同源接口工具。GUI 对话的服务端已接入 search/detail/status 调度，任务台使用同一适配器。首次通过连接器打开专用Chrome并由用户登录。只有本轮工具成功结果才能证明实时查询完成。

GUI 接口：`GET /api/state` 读取求职档案与本地请求令牌；`POST /api/state` 保存档案；`POST /api/chat` 在用户同意后提交档案与消息给模型。POST 使用 `X-App-Token`，不得把令牌复制到文档或日志。档案字段包括 resume、preferences、jobtitle、joburl、jd、messages。更新时先读再合并，保留用户已有字段。

网站核验、匹配、改写均分别报告实际完成状态。GUI 文案不代替网站证据，不把文本模型描述当作已执行浏览器动作。
