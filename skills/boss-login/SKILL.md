# BOSS 登录

使用当前环境提供的浏览器工具；在 Codex Desktop 使用 `mcp__cua_repl.js`。先读工具返回的文档，不假定不同 Agent 的 API 完全一致。复用已绑定的 Chrome 和 BOSS 标签页，跨会话重新发现标签，不保存固定 tab ID。

1. 查看当前页面。已有登录表单时直接继续，不重新导航；首次打开使用 https://www.zhipin.com/ 。城市可能自动选择，不由此推断用户求职地区。
2. 从新鲜页面状态定位“登录/注册”。本次验证过的语义调用：`await tab.playwright.getByRole('link', {name:'登录/注册',exact:true}).click()`。数字 AX 索引可能失效；出现 previous page 错误时重新观察并使用语义定位。
3. 点击后读取状态。只有标题或 URL 变成注册登录不代表表单加载成功；必须实际看到二维码、手机号/验证码输入框或明确登录方式。
4. 页面空白时再观察一次截图或 DOM。若返回首页，检查是否出现新标签页；没有新标签时可用页面已观察到的登录链接做一次直接导航。再次跳回则停止循环，说明实际现象，请用户手动打开入口。不要把跳回原因推断为反爬、账户问题或已登录。
5. 二维码出现时请用户用 BOSS App 扫码并确认。短信方式缺少手机号时向用户获取；不猜测或从其他来源提取。验证码由用户提供或在页面输入。不要保存密码、验证码、Cookie、二维码令牌到 Skill、日志或共享资产。
6. 遇到协议勾选、验证码挑战等按当前工具的确认规则办理；登录授权不自动授权注册新账户、接受新协议或发送求职消息。
7. 登录后以账户入口、个人中心等可见证据验证；没有证据就报告未完成。待用户操作时 `markHandoff()`，用户要求打开的最终页面用 `markDeliverable()`。

## 工具封装

[scripts/boss-login-tools.js](scripts/boss-login-tools.js) 提供接收已有 tab 的小型 JS helper；在支持模块导入的 Agent 浏览器运行环境中使用。CUA 环境不支持导入时，按函数体调用相同工具，不换用 shell 操作浏览器。先确认运行环境支持对应 API。

函数只打开入口、读取状态和保留标签，不填写身份信息、不提交登录、不判定成功。调用后由 Agent 根据页面实况决策。

主页打开成功，自动进入苏州站。语义点击登录后短暂出现 `/web/user/?ka=header-login` 与登录标题，随后返回首页；直接导航同样跳回。尚未看到登录表单、尚未验证成功登录。后续成功路径应在实操验证后补充，不能将预期步骤标记为已验证。

## 后续实操修正（2026-10-20）

手机号短信登录已成功，首页右上角出现账号头像、姓名、“消息”和“简历”。先前跳回/空白的观察不代表登录入口永久不可用。

- 登录页使用 `getByPlaceholder('手机号',{exact:true}).filter({visible:true})` 与 `getByPlaceholder('短信验证码',{exact:true}).filter({visible:true})`；存在隐藏的重复输入框，不能不加 visible 过滤，也不能固定 nth。
- 进入登录地址后等待实际可见输入框再填写；截图、DOM和AX有时呈现不同阶段，应以当前可交互表单验证，避免仅凭主页AX断言失败。
- 点击“发送验证码”后可能出现拼图。只有用户当次明确要求处理验证码后才尝试；根据新截图定位拼图与缺口，不保存固定拖动距离，失败刷新后重新观察。平台倒计时“已发送”才是短信请求成功证据。
- 用户提供短信验证码后填写；协议未勾选时，先就接受协议取得当次确认，再勾选并提交登录。不要保存短信验证码到任何文件。
- 最终以首页账号头像/姓名和“消息”“简历”入口确认成功。手机号、验证码、账号姓名均不写入通用工具或 Skill。

## 工具调用顺序与助手集成

工具导出 openLogin、fillPhone、requestSms、fillSmsCode、inspectLogin、keepLoginForUser。openLogin 会等待可见手机号输入框；如果已经在表单上，跳过 openLogin。验证码用字符串传入，保留前导零。每次操作后读取页面/截图，分别确认输入、短信倒计时、协议选中和账号入口。没有封装自动解验证码或自动接受协议的无条件工具。

本地求职助手在“BOSS 技能与工具”页面提供 Skill、工具源码下载、调用提示及最近实操结果。文件存在不等于 GUI 已接通浏览器；浏览器工具依赖当前 Codex 浏览器运行环境。不能在 GUI 文本模型中假装直接执行。最近登录成功是本次会话的历史核验；每次续跑都要重新核验当前账号状态。
